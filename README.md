# КИБЕР VENGANCE

The complete specification is in [`kiber-vengance.md`](kiber-vengance.md), the product status is in [`PRODUCT_PLAN.md`](PRODUCT_PLAN.md), and persistent memory for future sessions is in [`PROJECT_MEMORY.md`](PROJECT_MEMORY.md).

КИБЕР VENGANCE is a cinematic electro-rock composition instrument that runs entirely in the browser. `КИБЕР` is intentionally written in Cyrillic and `VENGANCE` in Latin characters. Its v6 hybrid engine combines five generated instruments with non-destructive audio lanes, slicing, arrangement, automation/modulation, performance, recording, Web MIDI Learn, routing, mastering checks, and full-song export.

## Studio interface

The four spaces are **Compose, Arrange, Live and Mix**. Sound opens the common inspector. Arrange contains audio editing and the sampler; Live contains the performance deck and clip launcher. All musical keyboards share multitouch behavior and styling. See [refactor architecture and parity](docs/REFACTOR.md), [design](docs/DESIGN.md) and [browser test prerequisites](tests/README.md). Source lives in `src/`, `index.html` and `public/`; `dist/` is generated by Vite.

## Installation and use

Node.js 22.12 or later is required for the server and tests. The published application is static and bundles Preact locally and requires no server runtime, accounts, telemetry, or secrets.

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:4173`. Web Audio requires a user gesture: press Play or touch a key to activate it.

To validate the complete product:

```bash
npm run check:full
```

`check:full` compiles the entire runtime with strict TypeScript, runs lint and unit tests, builds the static PWA, and executes real Firefox and Chromium workflows covering audio, accessibility, responsive design, launcher, arrangement, hybrid audio, precision mixing, local libraries, exports, performance recording, and Scratch Deck capture.

## Creating a song

1. Select a track in the sidebar or with `1`–`5`.
2. Choose or create an independent clip. Each clip can have 1, 2, 4, or 8 bars and a resolution from 1/64 to 1/4.
3. Add notes in the piano roll, drag them to move them, and use the right handle to change their duration. Drag over empty space to select multiple notes with a marquee; `Shift` adds the marquee to the existing selection. The drums provide kick, snare, closed/open hat, tom, percussion, and crash.
4. Adjust the two oscillators, ADSR, filter, unison, detune, glide, panorama, LFO, arpeggiator, and effects. The guitar uses a plucked-string model with pick attack, harmonics, and body resonance; its presets genuinely change the engine, not merely its name.
5. Draw cutoff, volume, or panorama automation below the piano roll.
6. Use key, scale, chords, riffs, bass lines, beats, quantization, and Mutation to generate controlled musical material.
7. Use `Backing` to create two to six sections of bass, pad, and drums in cinematic, driving, or dark styles while preserving your guitar and lead clips. In Arrange, you can later reassign any clip, set repeats, and reorder sections with buttons or drag-and-drop.
8. Set the clip or song locator to start playback at any step. The Arrange timeline also jumps the global song locator to a section.
9. Use `Export` to update the last linked destination or `Export As` to choose a format and new file. The panel supports WAV/MIDI, JSON/package backups, 16/32-bit depth, three sample rates, dither, normalization, dry/wet output, tail/region control, and selected stems.

Audio Studio adds any number of local audio lanes beside the generated instruments. Files and microphone takes are stored privately in IndexedDB and become non-destructive regions with start, length, source offset, gain, fades, pitch, source BPM and tempo-rate warp. Global Play schedules these lanes together with the arrangement, while Pause preserves the playhead and resumes an audio region from the matching source offset. Every region offers `Load Deck`, which creates a temporary Scratch Deck buffer that respects its trim, length, gain, fades, pitch, warp and reverse settings. The Scratch Deck buffer can also be committed back as a region. Song WAV and Project Package include loaded audio; plain JSON contains metadata only. Tempo-rate warp currently changes playback rate, so it also changes pitch—the browser-native engine does not claim independent pitch-preserving time stretch.

**Prism Keys** in Audio Studio turns any local audio file into a chromatic performance instrument. Its large multicolor 25-key keyboard gives illuminated per-note feedback and supports mouse, touch, velocity-sensitive MIDI, and the complete chromatic QWERTY row `A W S E D F T G Y H U J K` when armed. Use `Z/X` or the visible octave buttons to switch between C3–C4 and C4–C5. Root note, trim, tuning, level, filter, attack/release, reverse, polyphony, and gate/one-shot/loop modes persist in the v6 project. The private source blob lives in IndexedDB and travels with Project Package; use Record Take to capture a live sampler performance.

The global Automation Lab stores curve points for master or track parameters, offers Read/Touch/Latch/Write metadata, and supports LFO modulation routes. MIDI Learn binds incoming CC messages to these targets. Arrange stores tempo and meter events, while the note transform strip provides retrograde, inversion, double/half time and deterministic humanization.

Launch provides a five-track clip matrix for improvisation. Queue on beats or bars, stop tracks independently, control visible cells with MIDI notes 36–63, and capture the result as arrangement sections. Arrange adds multi-selection, copy/paste, fills, zoom, markers, exact timeline navigation, loop regions, and punch-in limits.

The transport supports 50–220 BPM, 4/4, 3/4, and 6/8 time signatures, swing, metronome, and a one- or two-bar count-in. Its dedicated Pause control stops at the current playhead without returning to the configured locator; the next Play continues from that position, including inside Audio Studio regions. Changing the time signature remaps note and automation positions to preserve the musical shape of the clips.

## Performance and editing

- `Space`: play/stop.
- `A W S E D F T G Y H U J K`: play or record a chromatic octave with the computer keyboard in Compose and Live; the visible octave controls move its range. Drums keep `A S D F G H J`.
- `1`–`5`: select track.
- `Ctrl/Cmd + K`: open the command palette with keyboard search and execution.
- `Shift + F`: toggle Focus, which hides the advanced racks and brings the editor to the foreground.
- `Shift + S`: toggle Solo on the selected track without interfering with the musical `S` key.
- `Shift + M`: mute/unmute the selected track.
- `Shift + V`: mutate the active clip (formerly `Shift + M`).
- `Shift + G/A/P`: open Forge, Arrange, or Perform.
- `Shift + L`: open Clip Launcher.
- `Shift + X`: open the Mix Console.
- `Ctrl/Cmd + E`: export the last format to its current destination.
- `Ctrl/Cmd + Shift + E`: open Export As and choose a format/destination.
- `Shift + N/D/V/Q`: create, duplicate, mutate, or quantize the active clip.
- `Shift + click`: multiple selection.
- `Ctrl/Cmd + A`, `C`, `V`: select, copy, and paste notes.
- Arrow keys: move the selection; `Alt + ←/→`: resize; `Shift` increases the step.
- `Delete`/`Backspace`: delete; `Ctrl/Cmd + Z` and `Ctrl/Cmd + Shift + Z`: undo/redo.

The visual keyboard responds to mouse and touch, sustaining voices until the key is released. Web MIDI records note-on, note-off, velocity, and per-channel expression: pitch bend, channel/poly pressure, and CC74 timbre; drum mapping follows the usual GM notes. The recording selector provides quantized or free mode: the latter preserves microtiming and sub-step durations, while `Quantize` can align them afterward.

### Two Scratch Decks

Live includes two independent bidirectional Scratch Decks, each driven by its
own `AudioWorklet`. Both can play at once with separate audio buffers, position,
speed, BPM, filter, stutter and platter gestures. The equal-power crossfader
balances Deck A and Deck B; the Program/Deck slider balances their combined
output against the composed song. `Capture Mix` renders the active clips into a mastered 1, 2, 4,
or 8-bar memory buffer; shorter source clips repeat cleanly to fill the selected
length. `Import Audio` also decodes a local WAV, MP3, OGG, WebM, or any other
audio format supported by the current browser directly into the deck. Audio
Studio regions can send their edited signal to Deck A with
`Load Deck`. Both platters support mouse, touch, wheel/trackpad, and keyboard control,
with interpolated forward and reverse playback, a smooth motor return, waveform
and playhead feedback, equal-power crossfading against the live program, a deck
low-pass filter, beat sync, brake, spinback, and tempo-derived stutter. Enter a
track's source BPM to use Sync; it changes playback speed and pitch to match
the project tempo. Browser-supported audio-output selection can route Cue A or
Cue B to a separate headphone output, outside the master recording. When the
browser offers no separate output routing, the Cue controls are disabled.

Scratch capture is intentionally non-destructive until `Resample Deck` is used: it does not modify the v6
project or its clips. The temporary buffer lives in memory and is cleared when
the page is reloaded. WAV/MIDI project export renders the composition itself;
it does not record a live Scratch Deck performance. Use **Record Take** in
Perform to capture the audible master—including scratching—and save that
real-time take. The browser normally records it as WebM/Opus. Take audio persists
in IndexedDB; v6 serializes its editable event log. Events can be trimmed,
quantized, retimed, changed, deleted, and replayed over the captured audio.
Editing events does not re-synthesize the already recorded waveform.

### Presets and local samples

Preset Vault searches and tags factory/user sounds, remembers favorites, saves the current instrument and clip character, and imports or exports JSON banks. Impact Sample Slots accepts local audio for all seven drum voices, with trim, tuning, attack, release, reverse, transient detection and automatic distribution of slices across free pads. Samples participate in live and offline rendering. Project Package exports the v6 JSON plus available drum, Prism Keys and Audio Studio assets.

### Mix Console and locators

The global locator selects an exact start step across arrangement scenes and
repeats. Each active clip also retains a session start position. Mix provides
stereo RMS/peak meters, peak hold, approximate momentary LUFS, dB faders,
pre-gain, pan, pre/post sends, track colors, Solo/Mute, master FX bypass, and a
loudness-matched A/B comparison. v6 adds group assignment, kick-triggered sidechain ducking, target LUFS/ceiling controls, and a mono check. Bus-level faders affect sustained voices.

Every clip preserves its own **character**: the Motion Engine arpeggiator and LFO, Signal Processing bypass and complete effect chain, and the six Vector Control macros. When switching clips, all three racks restore their independent values; duplicating or mutating a clip copies its character, while creating a new one starts from the active character. The preset and base synthesizer also belong to each clip; channel volume/pan remain track settings.

Each track card includes `S` (**Solo**) and `M` (**Mute**). Solo is exclusive: enabling it makes only that instrument audible, switches buses immediately even with sustained voices, and restores the complete mix when pressed again. It can also be enabled on the selected track by searching for `Solo` in `Ctrl/Cmd + K`. The state is respected when exporting WAV.

The synthesis, motion, effects, and macro racks can be collapsed independently; their state persists locally. On mobile, secondary racks start collapsed and tracks appear in a horizontal strip for faster access to the piano roll, without removing any controls. Knobs support vertical/horizontal dragging with increased range, fine adjustment with `Shift`, keyboard control, and touch-friendly `− / +` buttons. The project menu remains available on small screens.

Every track retains at least one clip. The `⌫` button deletes the active clip after a confirmation that identifies which sections use it; those references are automatically reassigned to another clip on the track, and the entire operation supports undo/redo.

The Spectral Deck interface uses track color-coding, a clear panel hierarchy, and highly legible illuminated states within a cyberpunk aesthetic. It avoids overlaid line textures, keeping the background clean and stable across displays with different pixel densities.

## Languages, tutorial, and help

The interface starts in English and can switch to Spanish using the `EN/ES` selector; on mobile, the same selector is available in the project menu. The preference is stored locally. Translation covers navigation, editing, arrangement, macros, commands, tutorial, dialogs, and accessible descriptions.

`Guide` starts a seven-step visual tutorial covering transport, tracks, synthesis, piano roll, arrangement, performance, and quick tools. The `?` button enables contextual help: focusing, touching, or hovering over any control reveals its purpose. All controls, including dynamically generated ones, also receive an accessible description.

## Projects and recovery

Versioned autosave is stored in `localStorage`. The project menu provides cinematic, minimal, performance and hybrid-audio templates; it can also duplicate a project, create named snapshots, restore automatic recovery points, export/import JSON or a project package, and inspect or forget linked export destinations. The v6 migration converts v2–v5 projects without changing their musical material. Interface scale is selectable from 80–120% and complements responsive/compact layouts.

## Architecture

- `src/core.ts`: v6 model logic, migrations, audio/automation primitives, transforms, performance data, launcher capture, arrangement, generators, history, and expressive MIDI.
- `src/audio.ts`: look-ahead scheduler, hybrid audio regions, global automation/modulation, polyphonic and sustained/MPE voices, guitar, drum synth, persistent FX buses, routing, master, analyzer, and offline WAV.
- `src/scratch-worklet.ts`: real-time bidirectional scratch playback, interpolation, looping, stutter, and position reporting off the UI thread.
- `src/features/dual-deck.ts`: second deck controls, BPM/crossfader workflow, optional Cue output, and responsive Live layout.
- `src/app.ts`: UI state, piano roll, free/quantized recording, MIDI, versions, diagnostics, export, and editing flows.
- `src/model.ts`: strict serializable contract. `npm run build` compiles the runtime modules into `dist/`.
- `tests/`: model, migrations, ten-minute transport, MIDI, Firefox, Chromium, accessibility, and responsiveness.

The scheduler programs 120 ms ahead and wakes every 25 ms. If a tab is suspended, it discards stale time rather than firing delayed events. Each track maintains one bus with independent saturation and distortion, tonal EQ, chorus, delay, and reverb; temporary voices disconnect when they end. The master adds EQ, compression, and limiting, preventing the graph growth that caused the former audio cutoff.

Offline WAV renders arrangement, automation, clip character, modeled guitar, synths, drums, and loaded local samples. It supports 16-bit PCM or 32-bit float, 44.1/48/96 kHz, normalization, TPDF dither, dry/wet mode, configurable tail, and loop-region export. The cancellable stems queue exports selected tracks plus a manifest. Cancellation is checked around each offline render and between stems; the browser cannot interrupt an `OfflineAudioContext` already rendering one stem. MIDI contains one tempo/time-signature track and five music tracks.

## Compatibility, PWA, accessibility, and limitations

The app includes a manifest and Service Worker for installation and offline use after the first load. The `Compatibility report` menu item displays and copies capabilities, status, and sample rate without telemetry. The suite is verified in headless Firefox and Chromium. The interface provides visible focus, accessible labels, high contrast, reduced motion, and a mobile layout without horizontal overflow; detailed editing remains optimized for desktop.

There are no runtime dependencies: only standard browser APIs. Web MIDI depends on support and permission; Safari/iOS still requires manual verification on Apple hardware. MP3/OGG/WebM import depends on the codecs exposed to Web Audio by the current browser; unsupported files produce a visible import error. Export handles, performance audio, and samples use browser storage. Clearing it removes binary assets, so plain JSON is not a sample backup—use Project Package. Unsupported File System Access browsers fall back to downloads. Performance capture uses the MediaRecorder codec exposed by the browser, normally WebM/Opus. Plugins, cloud storage, and multi-user collaboration remain outside the local static architecture.

### A different sound for each clip

Select a clip, open **Sound**, and choose Razor Choir, Neon Talon, Solar Vengeance or another preset. The clip remembers its preset, oscillators, filter, envelope, glide, unison and detune alongside its effects/macros. Switching clips restores their individual settings. New and duplicated clips inherit an independent copy; loading a factory or saved preset preserves the track mixer.

Existing projects acquire the same instrument in every clip on their track when loaded, so their original sound is preserved. JSON/Project Package and WAV/stems retain the new sounds; custom patches are not encoded in MIDI. Use the updated application to reopen these projects. Live effect tails remain on the shared track bus and can be colored by subsequent clip effects.

The **▶ CLIP** button beside the clip start locator becomes **Ⅱ PAUSE** during clip playback. Click it to pause at the current position, then click again to resume. It plays the active clips together; use Solo to hear only the selected track.

In Arrange, **LOAD TO COMPOSE** activates all five clips assigned to that section and opens the Compose editor. This provides a direct way to edit a complete section without selecting each track's clip manually.
